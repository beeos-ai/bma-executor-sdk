# Optional session context maintenance (SDK 1.7)

The executor protocol has typed `session.compact` and `session.compact_cancel` RPCs. Go agents may implement `AgentSessionCompactor`; TypeScript agents may implement `AgentHandler.compactSession` and `cancelCompactSession`; Go `AgentSessionCompactor` likewise requires `CancelSessionCompaction`. The `agent.context_maintenance` capability must be explicitly enabled. It must only be declared after the handler, durable publication, platform admission barrier and session-specific model authority are available. Go withholds the capability when the interface is missing; TypeScript refuses that invalid configuration. Python provides the generated types and methods, refuses both RPCs, and rejects advertising the unsupported capability.

A maintenance request binds session, operation ID, expected context version, last source input and model. Credentials may rotate when retrying the same semantic request. The handler must retain an idempotent receipt durably and return it for the same operation after process restart. A successful receipt increments the expected version by one and includes the complete UTF-8 summary, SHA-256 and positive source event count. The SDK validates these before returning. It cannot validate that the handler actually persisted the context.

Go and TypeScript reserve the agent session while maintenance settles. A concurrent turn, different maintenance operation or unresolved interaction cannot cross that reservation. Identical pending retries share the operation. Maintenance emits no ordinary turn or message events. Cancellation carries the same version/source/model identity and requires the handler to atomically fence late publication or return its already-applied receipt. The SDK fills `settled` from its own pending work, independently of the handler. A durable fence with `settled=false` still cannot release platform admission. Repeating cancellation after a process restart reconciles the same operation without another model invocation. Close waits for actual settlement. Network loss or RPC cancellation is not evidence of a rollback; the platform must retain its own database barrier and reconcile the operation with the same ID.

The platform supplies fresh maintenance-only model credentials. Never create a fake ordinary turn or reuse an old turn credential. A failed or canceled preparation must preserve the original context. A host must retain original history and references separately from the selected compacted model context. The SDK is a transport and concurrency seam, not the product feature or authorization service.
